# varyk-sql 0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `varyk-sql` 0.3.0: sqlx's `Any` driver gives way to concrete SQLite, Postgres, and MySQL pools, so Varyk 0.8's `Time`, `Uuid`, and `Bytes` bind and read as native columns, a `None` on Postgres is an untyped `NULL`, and MySQL's unsigned and small integers read with no cast, with the public surface unchanged.

**Architecture:** `Pool` and `Tx` keep their signatures and hold a private enum with one arm per driver, each arm behind its cargo feature. The query flow (`one_on`, `first_on`, `all_on`, `run_on`, `bind`) and the row deserializer become generic over a private `Driver` trait implemented for `Sqlite`, `Postgres`, and `MySql`, which carries the two things that differ by database: how a `varyk_std::Value` is bound, and how a cell is turned into a `Datum` from the driver's own type name. A field of the three new types asks for a string, so `Datum` hands times and ids over as their written form and binary columns raw; the field's own deserializer takes or refuses them.

**Tech Stack:** Varyk 0.8 (unreleased while this plan runs: the `feat/milestone-5c` branch of `Varyk-Lang/varyk`, with that plan's tasks 1 to 7 done; its compiler and `varyk-std` are numbered 0.7.0 until the release), Rust stable with MSRV 1.85, edition 2024, sqlx 0.8 (`runtime-tokio`, `migrate`, `tls-rustls`, `time`, `uuid`; drivers behind features), `time`, `uuid`, serde, `futures-core`, varyk-std 0.8. CI on GitHub Actions with Postgres 16 and MySQL 8 service containers; releases with release-please.

**Spec:** `docs/specs/2026-10-07-varyk-sql-0.3-design.md` ("spec §n"), the authority where this plan is brief; it extends `docs/specs/2026-10-03-varyk-sql-design.md` ("0.1 §n"). The compiler side is `Varyk-Lang/varyk`'s `docs/specs/2026-10-07-milestone-5c-design.md` ("M5c §n"): §2 (the three types), §5 (`varyk-std`: what a package's Rust sees, the serde contract, `Value`'s new variants), §6.2 (this package's contract), §6.3 (release order). Read the spec and those sections before any task.

## Review Focus

Inputs the spec implies but no listed test exercises, most likely to bite first. Each has a test in the task that owns the code.

1. A MySQL `varchar(100) collate utf8mb4_bin` column, which sqlx names `VARBINARY` because of its binary flag, still reads into a `string` field, as it did through `Any`; a binary column holding bytes that are not UTF-8 is the column-naming `Error`. Task 1.
2. A `Time` before 1970 with a fraction (`1969-12-31T23:59:59.5Z`): negative microseconds break a writer that uses `%` and `/` instead of Euclidean division. The SQLite text is `1969-12-31T23:59:59.500000Z`, and the instant is equal on Postgres and MySQL. Task 2 (unit test and the three databases).
3. An empty `Bytes` binds as a zero-length value, not as `NULL`, on all three databases (`data is not null` and its length is 0). Task 2.
4. A Postgres `-infinity` and a `timestamptz` of the year 10000 read into a `Time` are an `Error` naming the column, not a panic; the spec lists only `infinity`, and the raw-microseconds reader handles all three paths through the same checked conversion. Task 3.
5. A MySQL zero date (`0000-00-00 00:00:00`, stored after the test sets its session's `sql_mode` to `''`) read into a `Time` and into an `Option<Time>` is an `Error` naming the column in both, not a panic and not `None`. Task 3.

## Development Approach

- TDD per task: a failing Varyk `#[test]` in `src/tests.vr` (or a Rust unit test in `src/db.rs` for what needs no database), the minimal Rust, then the task's gate. Varyk tests follow the existing shape: a helper returning `Result`, opened with `match` and `assert`; values keyed by the test's name in `test` and deleted first through `ready`; `if pg()` for `$n` placeholders; a test that only applies to one database returns early on the others, as the MySQL tests do.
- The row deserializer is tested through `one`, `first`, and `all`, as in 0.1, since a row cannot be built outside sqlx.
- `src/db.rs` keeps its order (connect, `Pool`, `Tx`, the shared query flow, binding, the row deserializer, error mapping) and its comment style. The per-driver code is one private `Driver` trait with three `#[cfg]`-gated impls; the shared code is generic over it. Follow the existing `first_on` read-to-end pattern and the `statement_error` failed-flag pattern unchanged.
- Local databases, matching CI: `docker run -d --name varyk-sql-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=varyk -p 5432:5432 postgres:16` and `docker run -d --name varyk-sql-mysql -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=varyk -p 3306:3306 mysql:8`; ready when `docker exec varyk-sql-pg pg_isready -h 127.0.0.1 -U postgres` and `docker exec varyk-sql-mysql mysqladmin ping -h 127.0.0.1 -proot` answer (over TCP, as CI's health checks ask: each image first runs a socket-only server while it initialises). URLs: `postgres://postgres:postgres@localhost:5432/varyk?sslmode=disable` and `mysql://root:root@127.0.0.1:3306/varyk?ssl-mode=DISABLED`. A server's database outlives a run: after a migration file changes, `docker rm -f` the container and start it again, or sqlx refuses the changed version.
- A server leg, as CI runs it: rewrite the manifest's `default = ["sqlite"]` line to `["sqlite", "postgres"]` (or `"mysql"`; macOS sed is `sed -i ''`), run `varyk check && varyk test` with `DATABASE_URL` set and `RUST_TEST_THREADS=1`, then `git checkout -- Cargo.toml`. Never commit the rewritten line.
- **The gate**, run from the repository root with `VARYK_STD_PATH` set (until Task 5): `varyk check && varyk test` (SQLite); the Postgres leg; the MySQL leg; `RUSTUP_TOOLCHAIN=1.85 varyk test` (after `rustup toolchain install 1.85`); `rustfmt --edition 2024 --check src/db.rs`; then in the folder `varyk publish --assemble-only` prints, `cargo clippy --all-targets -- -D warnings` with the `--config` patch for each feature set: the default, `--all-features`, `--no-default-features --features postgres`, and `--no-default-features --features mysql` (the README documents single-driver builds, and `#[cfg]` arms hide warnings from the default build).
- Not needed: any change to `src/lib.vr` or the public signatures; a `url` crate (the scheme and the in-memory test split the URL text by hand); `chrono`; any `uuid` or `time` feature beyond the defaults; a fallback to `Any`; a change to `latest-varyk.yml` or `release-please-config.json`; README advice on migration folders per database (the spec does not ask for it).
