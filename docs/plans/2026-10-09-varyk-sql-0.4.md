# varyk-sql 0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `varyk-sql` 0.4.0: a query written with `$1`, `$2`, … runs on SQLite, Postgres, and MySQL alike, with a package-side scanner and checks on SQLite and MySQL, a MySQL rewrite of `$n` to `?`, the prepared-count check kept as the net, and every `?` query of 0.3 unchanged.

**Spec:** `docs/specs/2026-10-09-varyk-sql-0.4-design.md` ("spec §n"), the authority where this plan is brief. Read it before any task.

## Overview

Three tasks. Task 1 writes the scanner and the number checks as a pure function in `src/db.rs`, tested with Rust unit tests and no database. Task 2 wires it into the query flow (the borrowed `'q` lifetime, the MySQL rewrite with values in placeholder order, the count check's note) and adds the Varyk tests on all three databases. Task 3 moves the README, the demo, and the 0.1 spec to `$n`.

## Development Approach

- TDD per task: a failing test first (Rust unit tests in `src/db.rs` for the scanner, Varyk `#[test]`s in `src/tests.vr` for what needs a database), then the minimal code, then the task's gate.
- The scanner is one private function over the text and a `mysql: bool` (MySQL's lexical rules, or SQLite's), returning the `$n` and `?` positions it found or a scanner `Error`; the checks are a second private function over that result and the number of values. Both pure, so their unit tests need no database. Follows the existing pure helpers' style (`in_memory`, `counted`).
- One new `bool` constant on `Driver`, `REWRITES_DOLLARS` (true on MySQL only), following `COUNTS_PLACEHOLDERS` (a bool, not an enum: the impls are feature-gated, so an enum variant unused in a single-driver build is a dead-code warning under `-D warnings`). Scanning is gated on the existing `COUNTS_PLACEHOLDERS`, true on exactly SQLite and MySQL; its doc comment widens to say so.
- Varyk tests follow the existing shape: a helper returning `Result`, opened with `match` and `assert`; rows keyed by the test's name and deleted first through `ready`; a test for one database returns early on the others, as the MySQL-only tests do; exact messages asserted with `assert_eq`.
- Local databases as in the 0.3 plan's Development Approach: `postgres:16` on 5432 and `mysql:8` on 3306, ready when `pg_isready` and `mysqladmin ping` answer over TCP; URLs `postgres://postgres:postgres@localhost:5432/varyk?sslmode=disable` and `mysql://root:root@127.0.0.1:3306/varyk?ssl-mode=DISABLED`.
- **The gate**, from the repository root with the released `varyk` 0.8 (`cargo install varyk --version '^0.8' --locked`): `varyk check && varyk test` (SQLite); the Postgres leg and the MySQL leg (rewrite the manifest's `default = ["sqlite"]` to add the driver, run `varyk check && varyk test` with `DATABASE_URL` and `RUST_TEST_THREADS=1`, then `git checkout -- Cargo.toml`; never commit the rewritten line); `RUSTUP_TOOLCHAIN=1.85 varyk test`; `rustfmt --edition 2024 --check src/db.rs`; then in the folder `varyk publish --assemble-only` prints, `cargo clippy --all-targets -- -D warnings` for the default features, `--all-features`, `--no-default-features --features postgres`, and `--no-default-features --features mysql`.
- Not needed: any change to `src/lib.vr`, the public signatures (they keep `&'static str`), `Cargo.toml`, or CI; a cache or shared map of rewritten text (spec §3); scanning on Postgres; named placeholders; a `CHANGELOG.md` edit (release-please writes it from commit subjects only; the pull request description lists the queries that now fail loudly, spec §4).
- Work on the branch `feat/dollar-placeholders`; the spec and this plan are its first commits. Never on `main`; push and stop at green CI; the user merges. The pull request is squash-merged under `feat: $1 placeholders on every database` with no `BREAKING CHANGE` footer; no `<` or `>` in commit subjects; no attribution lines.

### Task 1: The scanner and the number checks

**Files:**
- Modify: `src/db.rs`

- [ ] add the scanner function after `counted`, taking the text and `mysql: bool`, reading quotes, quoted names (`` ` `` both, `[…]` SQLite only), the backslash escape (MySQL `'` and `"` only), and comments (`--` per dialect, `#` MySQL only, `/* */` both) as spec §2.1 lists
- [ ] recognise a `$n` only when the character before the `$` is not a letter (any non-ASCII counts), digit, `_`, or `$`, and the digits are not followed by a letter, digit, `_`, or `$`; parse the number with a checked conversion (no overflow, no panic), recording a number too large to hold (not an `Error`) so the checks order it after mixing and `$0`

- [ ] write unit tests: each quote and comment kind keeping `$1` as text per dialect; `'it''s $1'`; MySQL `'it\'s $1'`; SQLite `'a\'` then `$1` found; MySQL `5--$1` found and `-- $1` not; `price$1`, `$1$x`, `é$1` not placeholders; `'?'` beside `$1` not mixing; each check's exact message; an unclosed quote and an unclosed `/*`; `$99999999999999999999` the too-large message
