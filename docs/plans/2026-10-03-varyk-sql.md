# varyk-sql Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `varyk-sql` 0.1.0: a Varyk package on sqlx through which a Varyk program connects over TLS, migrates, queries, writes in a transaction, logs, and tests, against SQLite, Postgres, or MySQL.

**Architecture:** `src/lib.vr` re-exports four items of `src/db.rs`, a facade over sqlx's `Any` driver: `connect`/`connect_with` give a `Pool`, `begin` gives a `Tx`, and both carry `one`, `first`, `all`, and `run`, each taking a literal query and trailing scalar values (`varyk_std::Value`) and reading rows into Varyk types through a small serde deserializer keyed by column name. Every sqlx failure becomes a `varyk_std::Error` with a message the package writes.

**Tech Stack:** Varyk (the release that ships milestone 5b3's facade features), Rust stable with MSRV 1.85, edition 2024, sqlx 0.8 (`runtime-tokio`, `any`, `migrate`, `tls-rustls`, drivers behind features), serde, varyk-std. CI on GitHub Actions; releases with release-please.

**Spec:** `docs/specs/2026-10-03-varyk-sql-design.md` ("spec §n"); the compiler side is `Varyk-Lang/varyk`'s `docs/specs/2026-10-03-milestone-5b3-design.md` ("M5b3 §n"). Read both before any task.

## Global Constraints

- The package is a Varyk package: `Cargo.toml` has `[lib] path = "src/lib.vr"`, no `build.rs`, no `tests/`, `examples/`, or `benches/` directory (V0401), and is built only by `varyk` (M5b2). `src/db.rs` is the only Rust.
- `varyk` is the pinned minimum version the package needs (spec §7). While that version is unreleased, CI and local work use a `path` checkout of `Varyk-Lang/varyk` with `VARYK_STD_PATH` set to its `crates/varyk-std`, and the clippy step passes `--config 'patch.crates-io.varyk-std.path="<checkout>/crates/varyk-std"'`; the plan's last task removes that.
- No `unwrap`, `expect`, indexing that can panic, or any other crash-on-absence call in `src/db.rs`; every sqlx `Result` is mapped to `varyk_std::Error` (spec §3). No error message contains the URL or a database's "detail" field.
- `Cargo.toml` keys exactly as spec §5: `edition = "2024"`, `rust-version = "1.85"`, `license = "MIT OR Apache-2.0"`, `repository`, `keywords`, `description`, `homepage = "https://varyk.com"`, `categories = ["database"]`, `authors = ["Vlad Mickevic"]`; sqlx with `default-features = false`; features `default = ["sqlite"]`, `sqlite`, `postgres`, `mysql`.
- CI jobs are named `test` and `msrv` (spec §6, the branch ruleset); commit subjects carry no angle brackets (spec §7); no attribution lines in commits or pull requests.
- MVP: spec §8 is the cut list; implement nothing on it.

## Review Focus

Inputs the spec implies but no listed test exercises, most likely to bite first. Each has a test in the task that owns the code.

1. A query whose placeholder count equals the value count but whose values are of the wrong kind for the column (`"abc"` into an integer column on Postgres) is a database `Error` with the database's message, not a panic and not a silent `NULL`. Task 2.
2. `first` on a query that matches two rows gives the first, not an error; `one` on the same query gives the first as well (spec §2.3: no `limit` added). Task 2.
3. A `Tx` dropped inside a started task that is cancelled (the task dropped) rolls back, since the rollback is in sqlx's `Drop`. Task 3.
4. `migrate` on a folder that does not exist is an `Error` naming the folder, not a panic. Task 4.
5. A URL with a scheme of a driver not compiled in (`postgres:` with only `sqlite`) is an `Error` whose message names the missing feature and not the URL; asserted on the SQLite leg only, the no-secret rule on every leg. Task 1.

## Overview

Six tasks. Task 1 makes the repository a Varyk package that checks, connects to SQLite, and runs one test under CI. Task 2 adds the four query calls, value binding with the placeholder-count check, and the row deserializer. Task 3 adds transactions. Task 4 adds migrations. Task 5 runs the suite against Postgres and MySQL, adds the demo and the README. Task 6 wires release-please and makes the first release.

## Context

Spec sections are the anchors; the repository is empty at the start.

- Compiler side (M5b3): a `.rs` method with `T: varyk_std::serde::de::DeserializeOwned` returning `Result<T, varyk_std::Error>`, `Result<Option<T>, ..>`, or `Result<Vec<T>, ..>` (§2.1); a last parameter `Vec<varyk_std::Value>` written as trailing arguments (§2.2); a `&'static str` parameter taking a literal (§2.3); `varyk_std::Error` as a `Result`'s error (§2.4); `pub use` of one item (§2.5); `varyk add sql` (§2.6). `varyk_std::Value` is `Null | Bool | Int(i64) | Float(f64) | Text(String)`.
- Varyk has no `()` type: `migrate` and `commit` return `Result<bool, Error>` (spec §2.2, §2.4). Varyk's `self` is `&self` and `mut self` is `&mut self`; a method taking `self` by value cannot be called, so `commit` is `&mut self` over an `Option<Transaction>`.
- sqlx 0.8 facts the spec relies on (verified against sqlx 0.8.6 during review): `sqlx::any::install_default_drivers()` guards itself with a `Once`; `AnyPoolOptions::new().max_connections(n).connect(url)`; `AnyStatement::parameters()` gives `Option<Either<&[AnyTypeInfo], usize>>` (SQLite and MySQL a count, Postgres a type list); SQLite binds a missing value as `NULL` and ignores extra ones; `Migrator::new(path).run(&pool)` works on `AnyPool` and returns `Result<(), MigrateError>`; the history table is `_sqlx_migrations`; `sqlite::memory:` gives each pool one shared database; SQLite reports every integer column as 64-bit and every float as double, and has no boolean kind; `tls-rustls` is ring plus webpki roots; sqlx's default features pull in the macros.
- The reference for the Varyk side of the tests is `Varyk-Lang/varyk`'s `docs/language.md` ("Tests", "Configuration", "Async functions and tasks").

## Development Approach

- TDD per task: a failing Varyk `#[test]` in `src/tests.vr` first (async, on `connect_with(url, 1)`, opening `Result`s with `match` and `assert`), the minimal Rust in `src/db.rs`, then the task's gate.
- `url` in every test comes from `env::parse` into a struct with one `Option<string>` field `database_url`, falling back to `sqlite::memory:` (spec §6); a test with values picks its query by the URL's scheme with an `if` on `starts_with`; a test keys the rows it writes by its own name and deletes them first.
- `src/db.rs` is written as spec §5 orders it: driver install and `connect_with`/`connect`, `Pool` (`#[derive(Clone)]`) and `Tx`, the query methods on each over one shared binding function, the row deserializer, then the error mapping. Rust unit tests in `src/db.rs` cover the error mapping without a database; the deserializer is tested through `one` in the Varyk tests, since a row cannot be hand-built outside sqlx.
- The test schema lives in one helper of `src/tests.vr` from Task 2 on (`fn schema(db) ` running the `create table` statements through `run`), which Task 4 replaces with `migrate`.
- Rust style follows `Varyk-Lang/varyk`'s AGENTS.md (no hidden allocation, fail loudly, plain-word messages).
- The gate for every task: `varyk check && varyk test`, then `rustfmt --check src/db.rs`, then `varyk publish --assemble-only` and `cargo clippy --all-targets -- -D warnings` in the crate it writes (with the `--config` patch while the compiler is unreleased), then the 1.85 build of that crate (`rustup run 1.85 cargo build`).

### Task 2: Queries, values, and rows

Spec §2.3, §2.5, §2.6, and the rest of §3: the four query calls on `Pool`, trailing values bound with the placeholder-count check, and rows read into Varyk types by column name.

**Files:**
- Modify: `src/db.rs`, `src/tests.vr`
- Test: `src/tests.vr`, `src/db.rs` unit tests (`db_error`'s row and count cases)

**Interfaces:**
- Consumes: `Pool`, `db_error`, `url()` (Task 1).
- Produces: on `Pool`, `one<T>(query: &'static str, values: Vec<Value>) -> Result<T, Error>`, `first<T>(..) -> Result<Option<T>, Error>`, `all<T>(..) -> Result<Vec<T>, Error>`, `run(..) -> Result<u64, Error>`, each `pub async fn` with `&self`; in Rust, `async fn bind(conn: &mut AnyConnection, query: &'static str, values: Vec<Value>) -> Result<Query<'static, Any, AnyArguments<'static>>, Error>` (the shared binding function, used by `Tx` in Task 3; it prepares the statement only to read `parameters()`, then builds the returned query with `sqlx::query(query)` and binds, since a query built from the prepared statement would borrow a local) and `fn read_row<T: DeserializeOwned>(row: &AnyRow) -> Result<T, Error>` (the deserializer).

- [ ] Write tests on a table the test creates with `run` (plain SQL, keyed by test name): `run` gives the rows changed; `all` reads a `Vec<User>` by column name with extra columns ignored; `one` reads a struct, a scalar (`select count(*)`), and an `Option<i64>` (`select max(age)` on no rows); `first` gives `None` on no row and the first of two rows (Review Focus 2); `one` on no row is an `Error`; a `NULL` into an `Option` field is `None` and into a plain field is an `Error` naming the column; a missing column is an `Error` naming the field; `#[rename]` maps a field to a column; a `bool` field reads `0`/`1`; an integer column out of an `i8` field's range is an `Error` naming the column
- [ ] Write tests: zero, one, and three values bind; `Option<string>` `None` binds `NULL`; too few and too many values are each an `Error` naming both counts, on SQLite in particular; a text value into an integer column is a database `Error` (Review Focus 1; on SQLite, which coerces, assert the row instead)
- [ ] Write Varyk tests over `one` for the decode rule of spec §2.6: an integer column into an `f64` field, a float column with a fraction into an `i64` field refused, `0`/`1` into `bool`
- [ ] Implement `bind`: prepare, compare `parameters()` with the value count (skip when the driver reports none), bind each `Value` variant (`Null` as `None::<i64>`)
- [ ] Implement the four methods on `Pool` through `bind` and `read_row`, and `read_row` as a serde `Deserializer` over `AnyRow` keyed by column name (single-column rows for scalars and `Option` of a scalar; `Vec`, `HashMap`, and nested structs refused with an `Error`), following spec §2.5 and §2.6
- [ ] Extend `db_error` for the row and count cases of spec §3
- [ ] Run the gate
